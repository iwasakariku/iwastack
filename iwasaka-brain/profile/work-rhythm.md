## 一日の中での行動タイプの移り変わり

時刻帯ごとに行動タイプの構成比を取ると、全体平均（実装 25%・調査 18%・設計 14%・検証 12%・障害 11%・発信 8%・環境 7%・AI 基盤 5%）からのずれがはっきり出る。

| 夜（21〜23 時） | 33 | 環境・ツール設定 24%、AI 基盤整備 15%、検証 18% | 実装 15% |

読み取れる一日の型は次のとおり。

- **朝一番は道具を整える。** グローバル設定へのルール追記（9/11、9/16 の 2 件）、スキル・フックの改訂、CLI 更新確認などが午前に寄る。長いフルサイクル（20 ターン以上、49 件）の開始は午前 13 件・昼 15 件で、**重い仕事は昼前後に走らせ始める**。
- **昼過ぎに環境トラブルと計画。** ローカル環境の修復、dev 環境のイメージずれ、CI 失敗の切り分けと、チケットの親子分解・起票・計画書が 12〜14 時に集中する。
- **15〜17 時が実働のピーク。** 268 件と最多で、実装と調査が 49% を占める。Cursor の利用も 16〜18 時に最も多く（16 時 53・17 時 66・18 時 33 件）、エディタ内での短い確認・修正がこの帯に入る。一方 Claude Code は 10〜11 時（46・85 件）に偏り、**午前は Claude Code に長い仕事を預け、午後遅くは Cursor で手元の確認を回す**という二層構造になっている。
- **18 時以降は締めの作業。** PR 作成・push・チケット完了コメント、デイリー用の報告文、Slack 文面の起草が 18〜20 時に増え、設計・計画は 7% に落ちる。
- **21 時以降は業務外の道具いじりと長時間ジョブ。** 自作スキルの試走、設定ファイルの切り替え、利用枠の 5 時間ウィンドウを跨がせるためのスキャン待機（9/2 23:29）、AI 開発ライフサイクルフレームワークの試走（8/6 22〜23 時、8/8〜8/10 の 0〜3 時）。深夜 0〜3 時の 13 件のうち 4 件は 7/28 の 0:32〜0:57 に連続しており、MCP 遅延計測とバグ修正を一気に片付けている。
