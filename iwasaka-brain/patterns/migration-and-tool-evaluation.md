> [!summary] TL;DR
> 決定の理由と撤退条件を最初に明示し、「今ぶつかっている制約で選ぶ」。実装はせず調査のみ、段階的に選択肢を絞る。
> 公式情報とサンプルが食い違えば公式を正とし、既存テストを新版で実際に回して判断する。
> 全面採用よりも「必要な箇所だけ準拠」「部分的に採用」を選ぶ。

## いつ発動するか

ランタイムやベースイメージのサポート終了、ライブラリのメジャー更新、デッドコード検出ツールや UI テスト基盤の導入、外部 SaaS 仕様への追従、上流 OSS の更新取り込み、開発ツール（AI ハーネス・プラグイン）の試用。

## 手順・順番（観測されたもの）

1. **問題提起と段階的な選択肢。** サポート終了情報を示し「取得元を変えないといけない？」「一旦現バージョンを使い続ける場合にやるべきことは？」と段階的に絞る。実装はさせず調査のみ。公式情報を WebFetch で確認させ、CI/CD 設定を読ませて実態に即した優先順位を出させる（6 月）。
2. **理由と撤退条件を先に。** 「PoC 中に移行コストを下げたい」「とんでもないことになるなら後回し」を最初に明示し、4 系統（API 可用性・拡張・テスト 3 環境・ビルド可否）を並列実測（9 月）。
3. **実測を重ねる。** 「とりあえずアルファ版に上げられる？」「既存テストスイートを新版で回して」「2 系を自前ビルドできない？」「今どのバージョンで試した？」。上流から「新版で動くはず」と返事が来ても検証条件を確認する。
4. **制約で選ぶ。** 外部で得たツール比較（既存ツールと Rust 製代替）を貼って判断を求め、「今ぶつかっている制約で選ぶ」と既存継続を推奨された形で決める（6 月）。
5. **公式を正とする。** 外部 SaaS の公式仕様表とサンプル CSV を突合し、「フォーマットが変わるかも」と気づいてサンプルではなく公式ガイドを正としてズレを報告させる（8 月）。
6. **全面ではなく部分。** 上流 24 コミットの差分を「丸ごと更新はオーバースペック」と反転し自前ルールへ翻訳、上流監視ログを新設（8 月）。方法論は「全て導入するとオーバーなので部分的に採用」（8 月）。
7. **使用感を記録して判断。** 開発ツール試用では使用感レポートを md で作らせ、適用判断を明記。コスト表示やコンテキスト消費を計算に入れるよう指摘し、既存スキルで直らなかった経験から「工夫して取り込む形」を志向（8 月）。

## 判断の材料にするもの

- 公式ドキュメント・リリース情報・料金ページ（WebFetch）。
- Web 検索で各クライアントの要件、同業の対応状況。「参考になる事例とならない事例（リモートサーバーでないもの）」を自分で選別し、外部の評価記事を提示（9 月）。
- 自リポジトリの実コード・CI 設定・lock ファイル（AI の「未導入」を lock ファイルの記載で訂正）。
- 他リポジトリの運用（SP 計算、コミット規約）。
- OSS の実運用リポジトリ複数との構造比較（6 月、NestJS 構成）。
- 外部ハーネスとの対応表と差分（9 月）。

## 典型例

- **6 月・データ基盤**: 「ワークフローが使えない」環境制約を自分で把握しつつ、並列 Web 検索→主張抽出→敵対的検証→統合のリサーチハーネスで海外のベストプラクティスを調査。統合が壊れたら生素材から手組みレポート化。
- **7 月・データ基盤**: 3 万行規模の合成データ生成で、他ツールの生成例を「本当に上手くできてる？」と検証させ、自分の理解（内部で Python を書かせても出力上限、コード実行はセキュリティ懸念）を箇条書きで述べて検証を求め、JSON 案の限界を自ら指摘して Code Interpreter 案へ転換した。
- **8 月・データ基盤**: 乗り換えメリット調査を goal フックで自走させ、課題管理に起票しつつ不足分は上流 OSS にイシューを立てる方針。SP 見積に「1 ポイントぐらいじゃない？」と疑問を投げた。

## 落とし穴・避けていること

- 目標バージョンを明示して念押しする（「1.5.5 ではなく 1.4.5」）。統一の調査と周辺（Node 側）の調整も一緒に見る。
- 外部から渡された改善案の前提が誤っていないかを先に検証する（10 月、E2E 高速化）。
- 新規ライブラリ導入は可否を調査させ、推奨で追加した上で AI 駆動開発ルールへの組み込みも要求（7 月）。
- 「invoke じゃない API だと結構大変？」と選択肢の難易度を先に問う。

## 観測頻度

約 60 セッション、月 11〜23。9 月（バージョン統一・未使用依存・外部 SaaS 仕様）が最多。観測は多いが、長期の乗り換え完遂事例は少なく、調査・方針決定で止まるものが多い。
