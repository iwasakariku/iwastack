> [!summary] TL;DR
> 読者と分量と用途を先に指定し、メタ発言・英語混じり・固有名・コミット ID を排除して平易に書かせる。
> 自分の文章を正として AI は整形役。計画書は既存書式を踏襲し、非目標と採らなかった案を書く。
> セッション終了時に次回プロンプトとクローズ記録を残し、生成物 HTML はリポジトリに入れない。

## いつ発動するか

PR 本文、Slack 向け共有、CTO・管理層向けレポート、計画書、チケットのクローズ記録、引き継ぎメモ、記事。自作の「仕様→可読 HTML 化」スキルや Artifact を使い、スキル経由では対象だけ指定して構成はスキル側に委ねる。

## 書き方の指定（観測されたもの）

- **読者を指定する。** 「CTO が知りたい情報をしっかり組み込んで」「新卒でもできるインフラ手順書」「新規アサインでも分かるテスト仕様書」「社内メンバーが読んでも自然な文章で」「顧客公開版ではメタ的な文言を排除」。読者を管理層に変えて作り直させることもある（7 月）。
- **分量と形式を指定する。** 「Slack に貼る、箇条書き」「1〜2 文」「30 文字程度」「1 分で判断できる形」。固定フォーマット（一言／前提知識／未決／現状と残作業）を一文で全指定し、対象を替えて同形式を繰り返す（9 月）。
- **用語を平易に。** 「biz って何？もっと平易な言葉を」「英語混じりを日本語に」「技術用語に日本語説明を添えた平易な形へ」「正しい日本語で言うと？」。
- **具体 ID を消す。** 「コミットの ID は無意味なので削除して、関数や API などで説明して」。顧客固有名が混入したら「排除して」。
- **自分の文章を正とする。** 修正の因果関係を矢印付き図式（修正←症状←コミット）で自分が下書きしその形で PR に書かせる。用語補足・結論の 2 文を自分で書いて「これを修正して」と差し替え。回答文は本人が下書きし AI に「優しい素敵な言い方に」整形させる。
- **嘘にならないか確認する。** 本番で実行した結果を貼って設計書の記述が嘘にならないかを突く（7 月、機器連携）。「これも最新なんだよね？」と鮮度を確認。「推定」と注記されたシーケンス図は不要と削除。

## 計画書・チケットの書き方

- 既存計画書の書式を踏襲し、過去の確定方針との衝突を非目標へ振り分ける。
- 「非目標を捏造しない」「As-Is/To-Be は変わる時だけ」「工数は書かない」「score=(価値+緊急度+リスク低減)÷サイズ」「DoD と検証可能な仮説」（8 月）。
- チケットは「コードとか細かい部分は不要、目標・非目標だけ」「着手時にコードベースを調査するので事象だけ簡潔に」「難しいのでもっと手短に」。
- クローズ記録 4 項目（現状・済んでいること・残作業・未決・採らなかった案）を命令文で宣言し、以降も同様に書かせる（9 月）。「採らなかった案」が空なら会話履歴から埋めさせる。会話ではなくコード分岐から書き起こしたものはその旨を明記させる。
- 未決事項は別ファイルに分ける。「対応内容を整理して、非対応の内容を別ファイルに」。

## 引き継ぎ・同期

- 終了時に「次回の開始方法」を聞き、次セッション用プロンプトを作らせて貼って開始する（6 月、「main から切らない」ガード入り）。
- 「計画書本体も追従更新してから PR」「2 つの成果物の同時更新」「3 ドキュメントの同期更新」と文書同期を要求する。
- 「なるべく大きくは書き換えず、最新にして」と変更量を抑える。
- 全文保持ではなく学びの抽出＋アーカイブ化（6 月）。「不変なものと変わるものがごっちゃ」→具体値は消して取り方と想定だけ残す（7 月）。
- 「メモ配下は git 管理していないので、なくても動くように」依存を排除。生成物の HTML はコミットしない、「md だけ」。

## 典型例

- **6 月・データ基盤**: 進捗の Slack 共有を「箇条書き→リンク付き番号→素の URL」と 3 回の差分指示で収束させた。
- **7 月・データ基盤**: 設計書→HTML スライド化で競合調査メモも参照資料に加え、デザインとデータ可視化のスキルを順に適用。「結論ファースト・感動を一気に」の構成指示。
- **9 月・個人発信**: サブエージェント定義・フック実装・実走報告の Q&A を順に貼り込み記事化。敵対的レビューの 5 指摘を一つずつ判定し、試していない改修案は「試していない代替案」と明示。

## 落とし穴・避けていること

- 「メタ的なやつは避けて」「もっとシンプルに」と削る方向を優先。不要な節は自分で指定して削除。
- 「画面ごとにやっているので表の書き方が違う」と自分の作業単位に表を合わせさせる。
- 「DSL=SQL のこと？」と自分の理解を確認してから総括を書かせる。「前回も似たことやった？」と記憶を照合させる。
- 料金など変動するものは「完全には追わない」と割り切る。

## 観測頻度

65 セッション（6 月 31・7 月 16・8 月 15・9 月 9・10 月 4）。6 月は HTML レポートと Slack 共有、7〜8 月は CTO 向け資料と翻訳、9 月はチケットのクローズ記録と固定フォーマット要約。
