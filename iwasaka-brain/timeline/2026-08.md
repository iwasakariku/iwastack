> [!summary] TL;DR
> 8 月はデータ基盤（D1）一色。前半はセキュリティ所見の潰し込みと MCP サーバーの性能検証、中盤は AI 開発ライフサイクル（AI-DLC）フレームワークの試走と CSV 型推論の仕様確定、後半は本番障害の復旧を挟んで利用量計測・課金・請求 CSV 出力の実装へ一直線に進んだ。
> 「敵対的レビュー（反証）を通してから承認する」「数字は実測と出所で裏取りする」「計画 OK・push・マージは人が握る」がこの月に型として固まり、8/18 以降は /goal フックで数十体のサブエージェントを自走させる進め方へ移った。
> Cursor での短い一問一答は第 2 週で途絶え、以降は Claude Code 一本になった。

## 月の主題

**セキュリティ所見の収束（月前半〜）。** スキャン所見をサブイシューに分割し、RED→手動スモーク→実装→GREEN→レビュー→スモークのサイクルで回す体制を 8/4 に宣言、翌日から 5 件を並列 TDD で塞いだ。接続先検証では「一般的な SaaS はどうしているか」を確認してから簡単な対策を先に入れ、構造的な対策は別課題に切った。マージ可と判定した PR が別 AI の実測つき訂正で反転し、「検証に使う部品と接続に使う部品を実測で突き合わせる」教訓が残った。8/6 には「そもそもここまでやる必要あるの？」と前提を問い直し、個別の穴より権限分離を優先する方向へ転換。月末は WMS とデータ基盤の認証連携 PR を TOCTOU 観点で敵対的レビューし、指摘を OWASP/IPA 分類に対応付けさせた。

**MCP サーバーの性能と往復回数。** 月初はレイテンシ改善 PR のマージと sandbox での k6 計測。AI の「改善した」という主張 3 件を「8 秒のコールドスタートはどこいったの？」と一点突破で問い、1 回計測の差を改善と呼ばない姿勢を通した。8/21 には商談で遅く感じる原因をログ分析し、主因はサーバー処理ではなくエージェント側の逐次呼び出しによる往復回数だと特定。サーバー改修の前にプロンプト側で並列呼び出しを促して約 10 倍差を実測し、一括取得エンドポイントの計画書は往復数モデル（1+2N+M）で自ら定式化してから検証させた。

**AI-DLC フレームワークの試走と部分採用。** 8/6 に Bedrock 前提を外して導入し、使用感レポートを 3 版まで作成。8/8〜8/10 は MCP Apps 対応 UI を題材に要件→設計 3 ステージ→コード生成 7 ユニットを「done」と選択式質問への回答だけで完走させたが、テスト 545 件全緑でも実機接続で欠陥 3 件が出て「ホストをスタブしたテストでは手写しの契約を誰も検証していない」と結論。8/17 の計画書テンプレ更新と 8/18 の上流追従では「全部入れるとオーバー」と部分採用に徹し、本体は塩漬け・上流は概念の供給源と位置づけた。

**CI・テスト基盤の立て直し。** スプリントベース PR で CI が起動しない／OOM で落ちる問題を対照実験で特定して全ジョブ緑に、Server Action 攻撃面のガードレール CI を追加、2 ヶ月「一時的に」除外されていたアプリテストを復活（コスト約 40 秒）、Dependabot アラートを一括更新で大幅削減。E2E 基盤はペアワイズ因子表で計画し、敵対的レビュー後に「開発チームは 2 名、まずローカルから」と縮めた。

**CSV／Excel 取り込みの型推論。** 20 桁の整数 ID が壊れる PR レビューから「20 桁の CSV を作って実際に試したい」と実測で安全境界を出し、8/17 に「yes/no で決められる粒度まで詰めたい」と宣言して閾値・警告文・性能影響・演算時挙動まで確認して仕様確定。計画 MD を直接編集して実装に渡し、PR は 15 体の敵対的レビューで HIGH 6 件を潰した。月末は Excel 側の型推論が先頭行しか見ない非対称を突き止め、二段読みと「静かにデータが変質する経路の可視化」を別 issue に切った。

**利用量計測・課金・請求（月後半）。** /goal でテナント利用量の計測基盤と画面を 17 体のサブエージェントで PR まで自走させたのを皮切りに、保管容量課金は「月末だけ急減したら乖離しない？」という境界ケースから日次平均方式を決定。プラン CRUD・テナント別料金・締日ルール・管理メニュー隔離を敵対的レビューが収束するまで反復し、8/31 に請求 CSV 出力を 3 フェーズで実装して前月確定データで検収した。

**開発環境・オンボーディング・運用。** 新規参画者の障壁 9 件を起票し、セットアップをスクリプト 1 本・4 ステップに集約して fail-fast と自動有効化を足した。ローカル AWS エミュレータの代替調査を行い上流に issue を立てた。8/24 の本番障害（外部スプレッドシート連携の停止）は、設定・権限が正常なのに「出るはずのログが出ない」ことから旧イメージ稼働を特定し、本番操作は自分で実行して出力を貼る形で完全クローズした。

その他は D9 の OSS ドキュメント日本語化（20 ファイル、敵対的レビューで条件付き否決）と勤怠画面用の個人ブラウザ拡張、D2 の WMS 検証環境への lock ファイル反映判断、D5 の DB クライアントのクラッシュ診断が各 1〜数件。

## 週ごとの流れ

**第 1 週（2026-08-01〜2026-08-07、47 セッション）。** 月で最も密度が高い週。課題管理ツール移行の規約反映とドキュメント更新サブエージェントの新設から入り、MCP サーバーのレイテンシ PR マージ、k6 計測、sandbox ログの対照群比較を 2 日で片付けた。並行してセキュリティ所見のサイクル体制を宣言し、招待権限・ログイン文言・接続先検証を次々と PR 化、CI 失敗は「誰のせい？治さなくて OK」と帰責の切り分けだけ依頼した。8/6 に反証専任サブエージェントを自作プロンプトから追加し、同日 3 本の計画書を敵対的検証にかけて「CI が特定ベースで起動しない」という前提崩れを発見、「実測という語が実測の中身を保証しない」と記録した。squash-merge は履歴が消えるので使わない、push は明示許可してから、という git 運用もこの週に明言。週末は AI-DLC の導入試走、OSS 翻訳、個人用拡張と手を広げた。

**第 2 週（2026-08-08〜2026-08-14、29 セッション）。** AI-DLC の本番試走に大半を費やし、本人は「done」と選択式質問への回答役に徹した。設計前提が崩れた局面では AI の推奨と異なる「設計どおり実装」を自ら選び、完走後に実機で欠陥が出ると方法論への理解を「大幅に勘違いしてる？」と問い直した。8/10 は Cursor でローカル MCP の HTML リソースを「見れるようにして」と目で確かめ、カタログ消失は「バックアップとって実行して」で復旧し旧データは残した。週後半はデザイン同期ツールでパイプラインビルダーとカタログ画面のモックを反復し、「DB にしている意味はなんだろうか、意味ない気もしてきた」と永続化を取りやめた。CSV 型推論の桁あふれ、E2E 計画の敵対的レビュー、テスト除外の解消、Dependabot 一括更新もこの週。

**第 3 週（2026-08-15〜2026-08-21、26 セッション）。** 仕様を詰めて実装へ渡す週。CSV 型推論を yes/no 粒度で確定し、調査 4 体→実装 6 体→ゲート 1 体の多段構成で 13 コミットの PR を作り、敵対的レビューでブロッカーを全対応した。計画書テンプレを AI-DLC v2 から部分採用で改訂し、SP の相対見積ルールを明文化、上流 24 コミットから 3 概念だけ取り込んだ。worktree での並行作業（「他は別エージェントでやっている」）が常態化し、オンボーディング障壁の起票と実装、秘密管理サービスへの認証情報移行、ローカル AWS エミュレータの代替調査を同時に走らせた。8/18 から Stop フックの /goal 条件で AI を自走させる進め方が始まる。8/21 はスプリント末で、マージ状況をコードとチケットの二軸で突合し、MCP の遅さの主因を往復回数と特定、スプリントレビュー MD を自作スキルで生成した。

**第 4 週（2026-08-22〜2026-08-28、24 セッション）。** 8/24 の本番障害で幕が開き、復旧は自分でコマンドを叩いて出力を貼り digest 照合で確定させた。翌日はローカル環境の 3 障害を「0 から作れば生きてるかも」という自分の仮説で解消し、恒久実装は見送った。そこから利用量計測・課金の実装が一気に進み、/goal で 17 体・31 体・19 体規模のサブエージェント群を投入、敵対的レビューを修正ゼロになるまで 3 ラウンド回して過去月の請求額が書き換わる HIGH を捕捉した。課金基礎は日次平均、欠測は 0 で確定させない、コメントは 1 行で正本は 1 箇所、といった判断が連日積み上がった。8/28 は欠損補完の起票、認証連携 PR の敵対的レビュー、Excel 取り込みの根因確定、タイムゾーン報告の再現検証、請求 CSV 出力の計画と 7 セッションを消化した。

**第 5 週（2026-08-29〜2026-08-31、1 セッション）。** 「計画OK」で請求 CSV 出力を 3 フェーズ実装させ、途中で落ちたエージェントを再開して完走。独立コードレビュー 8 件は修正用エージェントに回し、自分は前月確定データのスモークで顧客向け文言の不自然さを拾って直させ、「ダウンロードOK、PRして」で締めた。

## この月に固まった判断・方針

- **成果物は敵対的レビュー（反証）を通してから承認・マージする。** 計画書・PR・翻訳・テンプレの別なく「敵対的に」と起動し、反証役には良い点を書かせず確信のない指摘は出させない。約 13 セッションで観測、8/6 の反証エージェント新設以降に定着。
- **数字と主張は実測と出所で裏取りする。** 1 回計測の差を改善と呼ばない、実物の CSV を作って試す、報告されたバグは自分で再現して正しい部分と行きすぎを分ける、テスト全緑でも実機で確かめる。約 15 セッションで観測。
- **計画 OK・push・PR・マージ・外部ツールへの書き込みは人が握る。** 「起票 OK、実装はまだ」「push を許可するので実行して」「マージは本人が行う」。/goal 自走でもこのゲートは外していない。約 10 セッションで観測、8/9 に組織ルールとして明文化。
- **スコープ外は別 PR・別課題・別 issue に切り、簡単な対策を先に入れて構造的な対策は分離する。** 約 7 セッションで観測。
- **説明は平易な日本語で、チケットは短く。** 「難しいのでもっと手短に」「意味不明、きちんと日本語にして」「新卒でもわかりやすく」。チケットは目標・非目標だけ、事象だけ簡潔に。約 7 セッションで観測。
- **前提を問い直す。** 「そもそもここまでやる必要あるの？」「DB にしている意味はなんだろうか」「未配線のままにするのはなぜ？」が優先順位の逆転や永続化の取りやめにつながった。5 セッションで観測。
- **コミットは意味単位に分け、小さな修正は 1 ポイントで見積もりチケットを切らない。** 5 セッションで観測。
- **競合する先行実装があれば自分の実装を取り下げてでも相手を優先し、差分を先に確認する。** 3 セッションで観測。
- **フレームワークは部分採用し、オーバースペックを避ける。** 本体は塩漬け、上流は概念の供給源。3 セッションで観測。
- **操作の前に退避する。** 古いスクリプトは新しい方の動作確認後に消す、移行はバックアップを取って旧データを残す、旧ボリュームは退避してから作り直す。3 セッションで観測。
- **仕様は yes/no で判定できる粒度、または適用条件を一文で確定してから実装に渡す。** CSV 型推論と締日ルールの 2 セッション（単発寄り）。

## この月の AI の使い方の特徴

- **サブエージェントの大量並列が常態化。** 観点別 10 体超（8/3）、計画裏取り 9 体（8/4）、PR 検証 15 体（8/17）、実装 17〜31 体（8/24〜8/26）。本人は方針決定・競合優先順位・結果の突合に専念し、38 セッションで委譲が記録されている。
- **反証専任エージェントと実証系の 2 本立て。** 8/6 に自作プロンプト（良い点は書かない／一次情報で裏取り／深刻度と確度を添える）で作成し、以降は計画書・PR・翻訳に横断適用。実装者とレビュアーのモデルを切り替える運用も明言（8/5、8/13）。
- **/goal（Stop フック）による自走は 8/18 から。** 完了条件を「ログイン画面が開くまで」「修正がなくなるまで」と観測可能に書き、起票 20 回・Bash 250 回超の長いセッションを任せつつ、計画承認とチケット書き込みのゲートは残した。7 セッションで観測。
- **AI-DLC では回答者に徹する。** 発話は「done」と番号回答のみで、14〜29 問の選択式質問に答えてステージを進め、回答間の矛盾検出は AI 側に担わせた。
- **生出力を貼るのが質問。** エラーログ、aws CLI 出力、DOM ダンプ、クラッシュレポート、スモーク結果表をそのまま貼り「これって何？」「なぜ？」「合ってる？」を添える。10 セッション超で観測。
- **自分の成果物を入力にする。** 自作プロンプト（8/6）、直接編集した計画 MD（8/17）、自分で書いた並列呼び出しガイドと往復数モデル（8/21）、自分で計算したコスト試算（8/3）を AI に渡して検証させる。
- **Cursor は第 2 週まで。** 「何中？」「ほい」「繋いで」「#n をレビューして」といった一問一答が 30 件、8/10 を最後に Claude Code へ一本化した。
- **デザインツールと課題管理 MCP、メモリと worktree の併用。** デザイン同期ツールでモックを 31 回反復して検討結果をチケットへ投稿、起票スキル（既存確認→プラン→起票案で停止→承認後作成）を経由して起票、次に進む前に引き継ぎをメモリへ残してコンテキストをクリア、並行作業は worktree で分離（6 セッション）。

## 未完で翌月に持ち越した事項

- 請求 CSV 出力 PR と、プラン CRUD・テナント別料金・締日ルールのスタック PR 群は直列マージの判断待ち。利用量計測の push と課題管理への追記も承認待ちで停止（8/25）。
- グループ削除後に利用量内訳へ項目が残る問題は「単純なフィルタでは合算と内訳が不一致になる」制約つきで起票のみ。「静かにデータが変質する経路」の可視化 issue、Excel 二段読みも方針確定まで。
- MCP メタデータ一括取得エンドポイントは敵対的レビュー後の計画書改訂まで。並列呼び出しガイドのスキル化も方針のみ。
- E2E テスト基盤は「まずローカル運用」へ縮小した計画段階。フロントのテストが CI で走らない課題（8/7）も記録のまま。
- Lambda ベースイメージ更新と DuckDB バージョン統一はワーキングツリーに作成・未コミット（8/24）。変換ステップの数値入力でマイナスが NaN になるバグは計画中で、別担当ブランチの既存修正との整理が必要。
- セキュリティ面では、接続先検証の残課題を権限分離優先へ組み替えた計画、スキャン用プラグインの新旧差分調査（結論未記録）、認証連携のレビュー指摘に残対応あり。
- AI-DLC で生成した MCP Apps UI は実機欠陥 3 件が未修正。スプリントブランチから main への統合 PR 未作成（8/21）。
- デプロイ速度は arm64 上の amd64 エミュレーションと直列フルビルドが主因と判明したが対策未着手。デプロイスクリプトのエラー可視化改善も提案止まり。
