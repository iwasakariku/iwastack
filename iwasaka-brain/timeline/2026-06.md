> [!summary] TL;DR
> 6 月は、データ基盤の Web 管理画面を機能ディレクトリ単位で監査・リファクタする「監査サイクル」を Cursor で 10 機能ぶん回し切り、中旬に Claude Code へ主戦場を移してバグ修正フルサイクルスキルと NestJS API の構造再編（フェーズ型リファクタ）を立ち上げた月。
> 月の後半で「契約不変＋検証ゲート全緑なら PR 作成まで無人で進めてよい」という運用が確立し、人間の仕事は計画承認・実機スモーク・マージへ絞られていった。
> 一貫していたのは「計画確認とスモークは人間ゲートとして残す」「AI の完了報告は実機・実コードで裏取りする」「同根のバグは横展開してまとめて潰す」。

## 月の主題

**データ基盤（D1、295 件）** が圧倒的な中心。前半は Web 管理画面（Next.js）のリファクタ監査、中旬はスプリントのバグチケット消化、後半は NestJS API の Fat Service 分割・モジュール集約・列挙値 SSOT 化という構造再編に軸足が移った。月末には倉庫データをデータレイクへ抽出する ETL 用 SQL の整備と、顧客の検証環境データを MCP 経由で分析して HTML レポートにまとめる仕事が入ってきた。

**WMS（D2、13 件）** は倉庫制御システム（WCS）との連携一覧の資料化、リリース時の環境設定差分、本番の帳票予約タイムアウト（499 多発）の真因調査、データレイク向け抽出 SQL の作成。**機器連携プロキシ（D3、6 件）** は TCP セッション構成の図解、本番ログの接続エラー切り分け、疎通テスト当日の手順書と想定問答、SEQ-No 制御の仕様準拠確認。**AI 基盤・個人ツール（D4/D5/D9）** は会話ログの自動保存フック、利用量をステータスバーに出す拡張機能、スキルのグローバル配置、ファン制御 CLI など小粒だが、月全体の仕事の仕方を変えた仕込みが含まれる。

## 週ごとの流れ

**第 1 週（6/1〜6/7）** は記録がない。会話ログを個人ナレッジベースへ自動追記する Stop フックを Cursor 側に作ったのが 6/8 で、この月の記録はそこから始まる。

**第 2 週（6/8〜6/14、Cursor 211 ブロック）** は Web 管理画面の監査サイクル一色。まず自作の監査スキルに「ブランチ作成からコミットまでは自走、push と PR は人間承認、計画確認は唯一のゲート」という自動化範囲を定め、経営層視点のリスクレビューで「戻すのは 1 点だけ、他はガード節で前進」と線を引いた。その上でテナント管理・データセット管理・実行履歴・テナント選択・ワークスペース・タグ管理と 10 機能を回し、各機能で「監査を続けて」→検査→壁打ち→「計画OK」→実装・コミット→他 AI レビュー→自分でスモーク→振り返り→PR の 8 ステージを踏んだ。ダイアログが閉じる不具合では自分がコンソールログを取る役に回って 4 往復でライブラリ仕様に辿り着き、試行錯誤の 14 コミットを意味単位に squash してからレビューに出した。週後半は 1 ヶ月運用想定のダミーデータ投入、モバイル表示崩れの実機確認、経営層向け進捗 HTML と続き、6/10 には課題管理ツールから未対応バグ 24 件を取り込んで難易度・影響範囲・重複の軸で分類し、ユーザー管理の関連 5 件をまとめて設計を揃えて直した。

**第 3 週（6/15〜6/21、Claude Code に移行）** は仕組みづくりの週。6/15 に「このリポジトリでもっと効率よくバグ修正するには」という問いからバグ修正フルサイクルスキル（再現→分類→壁打ち→計画→実装→レビュー→スモーク→PR）と再発パターンのカタログを新設し、以降のバグ修正はすべてこれに乗せた。6/16〜17 は git worktree で並行しながら、権限不備・テナント切替後のコンテキスト伝播・時刻表示・再実行と日付フィルタなど同根のチケットを 1 PR に束ねて消化し、レビューがバグを見逃したときは「計画・コードレビューが機能していない」と工程自体を問題視した。6/18 からは API 側の肥大化したサービスの分割設計に入り、「分けすぎは本末転倒、一層足す程度」「本番稼働前の今しかない、思い切った Tidy First」と制約と時機を自分で置き、OSS の実運用リポジトリ複数と比較させて設計書群を PR 化。6/19 はその資料を上長向け 1 ページ HTML にして根拠のない主張を潰し、機器連携プロキシの疎通テスト当日に備えて「一問一答で共通認識を作る」役割定義で手順書と想定問答を整えた。

**第 4 週（6/22〜6/28）** は API 再編の実装を一気に進めた週で、6/25 だけで 27 セッションある。Fat Service の責務別分割、forwardRef 撤去、コネクタ集約、コントローラのモジュール畳み込み、エラーハンドラ層の第一級化、入力起因エラーの 4xx 化、機能モジュールのディレクトリ集約、ファサード撤去とガード一元化、コネクタ別ディスパッチャ化、と PR を 1 つずつマージしながら進めた。この過程で「契約（URL・swagger）不変かつゲート全緑の構造移動は PR 作成まで確認なしで進める、振る舞いが変わる変更は PR 手前で止めてスモーク」という運用が固まり、6/25 に型チェック→テスト→lint→swagger 差分→DI 起動スモーク→PR を固定した出荷スキルを作って以降の全フェーズで使った。並行して列挙値の置き場ルール、デッドコード検出ツールの常設、スキーマレジストリの責務分離を別フェーズとして計画化し、重複を解消したマスター着手順（減らす→動かす）を docs PR で先に確定させた。合間に WMS 本番の帳票予約タイムアウトをログ・スロークエリ・FPM slowlog を自分で取りながら追い、ロック仮説を捨ててワーカー飽和に辿り着き、6/26 にはプロキシの電文制御について仕様準拠の未確認事項を照合表で洗い出した。

**第 5 週（6/29〜6/30）** は次スプリントの準備と越境。シークレット取り扱いの報告をデータの流れる方向で二分して対応要否を判定し、バグチケット 8 グループの実装計画を 1 グループずつ承認しながら揃えて「対応方針そのものが間違っていないか」を監査させた。WMS の DB からデータレイクへ抽出する在庫・入荷・作業時間の SQL を既存クエリの規約に合わせて作り、ETL ツールの制約（複数文不可・メモリ不足）に当たるたびに DuckDB のパススルー関数で包む形へ書き換えた。顧客データの分析では「データがある期間に絞る」「顧客公開版からメタ的な文言を排除する」と読者を切り替えて 2 本のレポートを作った。月末は統合ブランチ→feature の 3 層構成で最初の修正をローカルマージし、30 件のコンフリクトを解消した大規模 PR を push して「マージは自分で行う」で締めた。

## この月に固まった判断・方針

- **計画確認・スモーク・push/PR は人間ゲートとして残し、その間は自走させる。** 「計画OK」「スモークOK」「PR作って」の承認語で段階を進めるセッションが 30 件超。push と PR を自動化しないと明言した例も 19 件。
- **スモークは自分の手で、想定ロールのユーザーで行う。** スモークに言及するセッション 40 件。最上位権限での確認は偽陰性になり得るという学び（6/18）から、権限系は一般ロールで試す（6/23 に手順書へ反映）。
- **AI の完了報告・メモリ・コミットメッセージを鵜呑みにせず、実機・実コード・実リポジトリで裏取りする。** 実測・裏取りに触れるセッション 39 件。「何も変わってなさそう、ハードリロードもした」と差し戻す、メモリ上「未マージ」の PR を fetch で実測してから分岐する、など。
- **同根・同種のバグは横展開してまとめて直す。** 1 件直すたびに「他にそういう箇所はない？」「横展開はある？」と問うのが 15 件、同根チケットを 1 PR に束ねるのが 6 件（6/17 に集中）。未起票でも同根なら同じ PR で潰す。
- **既存画面・既存機能のパターンに揃え、過剰分割は戻す。** 13 件で「既存に合わせる」を選び、6 ファイルに分かれた読み取り層を 1 ファイルに統合、自前のシンタックスハイライトを YAGNI 指摘で削除（-330 行）など 8 件で「削る」判断。
- **契約不変＋ゲート全緑なら PR 作成まで無人、振る舞い変更は人間スモーク。** 第 4 週に確立し、出荷スキルを通したフェーズ PR 8 件以上で運用。ゲートが 1 つでも赤なら緑を装わず止める。
- **他 AI によるクロスチェックを実装前後に挟む。** 壁打ち・他 AI レビューが 22 件（第 2 週に集中）。結果は「やる・見送り・後回し」を自分で仕分けて渡し、採否は自分で決める。
- **分からない用語は承認前に必ず聞き、ログ・エラーは加工せず生のまま貼る。** 「〜って何？」「なんのこと？」が 8 件、原文貼り付けに観測を一言添える型が 11 件。
- **ドキュメントは読者と媒体に合わせ、推定や未検証の how-to はコミットしない。** 経営層向け HTML、チャット向け箇条書き、顧客公開版からのメタ記述排除など 10 件。
- **セッションを跨ぐ前提はメモリや定型プロンプトに埋め込む。** 引き継ぎメモ・次回プロンプト・メモリ更新に触れるセッション 15 件。

## この月の AI の使い方の特徴

前半は Cursor のエージェントに自作の監査スキルを「司令塔」として走らせ、コミット文生成・HTML 化はスラッシュコマンドで定型化、レビューは別の AI にプロンプトを貼ってリレーする使い方。本人の発話は「監査を続けて」「計画OK」「コミットして」「ええやん、コミットして」と極端に短く、判断を渡したら実装・型チェック・コミットまで一任し、代わりにスモークとレビュー指摘の採否を自分が握る分担だった。

6/15 以降は Claude Code に移り、使い方の質が変わる。サブエージェントを使うセッションが 37 件、多観点レビューや敵対的検証のワークフローが 14 件、最大で 1 セッションにワークフロー 9 本・サブエージェント 19 体。調査・レビュー・影響範囲確認を並列に投げ、自分は制約の明示（「分けすぎない」「契約不変」「ビルド成果物は読ませない」）と実機確認に集中した。スキル（バグ修正フルサイクル・出荷）で手順を固定し、メモリとハンドオフ文書で長丁場をマージの節目でクリアしながら継続。課題管理ツールやデータレイクへの MCP 接続、Stop フックによるゴール強制も使い始めた。一方で、AI が勝手に広げた変更範囲は即座に戻させ、確認なしに作業を始めた場合は「勝手に始めないで」と止めるなど、自走の範囲は自分が決めるという姿勢が崩れていない。

## 未完で翌月に持ち越した事項

- スプリントのバグ修正は 8 グループぶんの計画が揃ったのみで実装は未着手。3 層ブランチ構成の最初の feature はローカルマージまで、push と統合は翌月。

- 顧客向け分析レポートの 1 本はデータ構造の把握で記録が終わっている。
- 機器連携プロキシは電文制御の仕様準拠に未確認事項が残る（対応判断は未記録）。WMS のドキュメント管理ルールはリサーチ素材を回収した段階で策定は未了。
