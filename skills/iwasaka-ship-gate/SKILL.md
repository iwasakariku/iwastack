# iwasaka-ship-gate（出荷ゲート・PR・Done記録）

「チケット駆動・PR統合・マージの進め方」（`patterns/ticket-and-pr-flow.md`）および「ドキュメント・引き継ぎの癖」（`patterns/documentation-habits.md`）に基づく実行スキルです。

## 出荷前ゲート（Shipment Gate）

PRを作成する前に、以下のコマンドを一括実行し、全緑（All Green）であることを確認します。
1つでも赤があればPRを作成してはなりません。

1. **型チェック (Type Check)**: `tsc --noEmit` やビルドコマンドで型エラーが0件であること。
2. **ユニットテスト・統合テスト**: すべてのテストスイートがパスすること。
3. **Lint**: コード規約違反がないこと。
4. **スキーマ / Swagger / 生成物の再生成**: スキーマ変更がある場合、生成物を更新し差分を確認。
5. **DI / 起動スモーク**: アプリケーションが正常に起動・初期化できること。

> [!IMPORTANT]
> **無人進行の唯一の例外**:
> 「契約不変かつゲート全緑の純構造移動」のみ、人間承認を挟まずにPR作成まで自動で進めてよい。
> それ以外の振る舞い変更を含む変更は、必ず人間による実機スモークを経てからPRを作成する。

## PR作成のルール

- **マージ方式**: **merge commit 必須**（`squash-merge` は過去の経緯・履歴構造を破壊するため禁止）。
- **ベースブランチ**: 規約ファイルより実マージ履歴を優先し、スプリント統合ブランチをベースにする。「mainから切らない」。
- **PRの粒度**:
  - 1PR = 1サブフェーズ。
  - 前PRがマージされてから次のブランチを切る（スタックしない）。
  - BEとFE、生成物の再生成、ドキュメントはコミットを適切に分ける。

### PR本文テンプレート

```markdown
## 概要
- 一言でいうと: [変更内容の要約]

## 修正の因果
[コミット / 原因] ---> [発生していた症状] ---> [今回の修正内容]

## 変更内容
- 

## 受入基準 (DoD) との突合
- [x] 基準1: 実装・検証済み
- [x] 基準2: テストコード追加

## 検証結果 (エビデンス)
- [x] 出荷前ゲート (型 / テスト / lint / 起動) 全緑
- [x] 手動スモーク確認済み (ロール: 一般ユーザー)
```

## Done化とクローズ記録（Close Record）

ユーザーから「マージした」の合図を受け取った後、チケットに以下の定型フォーマットでクローズコメントを残します。

```markdown
### 完了報告

**一言でいうと**: [1文で簡潔に]
**読む前に知っておくと迷わないこと**: [前提知識・注意点]

1. **実施内容**:
   - 
2. **採らなかった案とその理由**:
   - [案A]: [不採用とした理由]
3. **残った未決事項**:
   - [フォローアップが必要な事項 / 別イシュー番号]
4. **現状と残作業** (未完了で中断する場合のみ):
   - 現状: 
   - 残作業: 
```
